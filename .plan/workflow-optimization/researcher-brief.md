# Research: Workflow optimization for coding agents and Pi Cartographer

## Summary
Best current guidance converges on **small, composable workflows with tight context budgets** as the default, escalating to autonomous or multi-agent systems only when task breadth, uncertainty, or parallelism justifies sharply higher token cost. For Pi Cartographer, the strongest path is a durable plan/retrieval/implementation/validation loop backed by repo maps, lexical/symbol retrieval, bounded evaluator loops, and measured prompt/retriever optimization.

## Findings
1. **Prefer workflows before agents.** Anthropic’s agent guidance explicitly recommends starting with direct LLM calls and simple workflows such as prompt chaining, routing, parallelization, orchestrator-workers, and evaluator-optimizer loops; use autonomous agents only when the model must dynamically decide steps and tool usage over time. **Pi influence:** make Pi’s default units explicit phases (`plan -> retrieve -> implement -> validate -> summarize`) with typed artifacts, not an always-on autonomous loop. [Anthropic: Building effective agents](https://www.anthropic.com/research/building-effective-agents)

2. **Use orchestrator-worker only for high-breadth work.** Anthropic’s multi-agent research system uses a lead agent to decompose research and delegate parallel subagents, but Anthropic reports materially higher token use, including roughly **15x** token usage in its multi-agent research setting, making it worthwhile mainly when parallel exploration or context breadth is the bottleneck. **Pi influence:** launch workers only for independent retrieval/review/evaluation branches; require each worker to return a compact cited artifact, never a full transcript. [Anthropic: How we built our multi-agent research system](https://www.anthropic.com/engineering/built-multi-agent-research-system)

3. **Repo maps are proven context-budget infrastructure.** Aider’s repo map sends a compact, ranked map of files/classes/functions/signatures rather than whole files, using code structure and graph ranking to fit useful repository awareness into a small token budget. **Pi influence:** maintain an AST/symbol map with centrality and recency/mention weighting; treat it as navigation context, then fetch exact snippets before edits. [Aider repo map docs](https://aider.chat/docs/repomap.html) [Aider repo map design note](https://aider.chat/2023/10/22/repomap.html)

4. **Lexical and symbol search should be the default for code.** GitHub’s modern code search and Sourcegraph/Zoekt are built around fast literal, regex, trigram, and symbol-oriented indexing because code work often starts from exact identifiers, strings, paths, diagnostics, and APIs. **Pi influence:** prioritize `rg`/Zoekt-style lexical search, symbol lookup, call/reference maps, and file-line snippets; add vector/RAG only as a secondary/hybrid path for natural-language concepts, docs, issues, and summaries. [GitHub: technology behind code search](https://github.blog/engineering/architecture-optimization/the-technology-behind-githubs-new-code-search/) [Sourcegraph Zoekt](https://github.com/sourcegraph/zoekt) [ripgrep](https://github.com/BurntSushi/ripgrep)

5. **Long context still needs structure and retrieval discipline.** Anthropic’s long-context guidance recommends placing large context before the query, structuring with tags, and asking the model to ground answers in quoted evidence; prompt caching can reduce repeated cost/latency for stable context. **Pi influence:** cache stable project instructions and repo maps, but keep dynamic snippets small, cited, and ranked; reserve output budget and make the model quote or cite file ranges before high-risk edits. [Anthropic long-context tips](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/long-context-tips) [Anthropic prompt caching](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching)

6. **Agent-computer interfaces matter as much as model choice.** SWE-agent’s ACI work shows that coding performance improves when the agent gets an interface designed for software engineering: concise file viewing, search, edit, diagnostics, and test commands rather than raw shell-only interaction. **Pi influence:** expose bounded tools that return compact summaries plus file/line handles: repo-map query, lexical search, symbol lookup, dependency edge lookup, safe edit preview, diagnostics, and targeted test execution. [SWE-agent paper](https://arxiv.org/abs/2405.15793) [SWE-agent docs](https://swe-agent.com/latest/)

7. **Coding-agent best practices emphasize project memory, exploration, and tests.** Claude Code guidance stresses maintaining project instructions/memory, letting the agent inspect the codebase, using custom repeatable workflows, and closing the loop with tests/linting. OpenAI Codex/Codex CLI similarly centers project instructions, sandboxed code editing, and command execution. **Pi influence:** read `AGENTS.md`, `CLAUDE.md`, and local conventions into a stable instruction layer; generate a validation plan before edits and run the cheapest relevant checks first. [Claude Code best practices](https://www.anthropic.com/engineering/claude-code-best-practices) [Claude Code memory](https://docs.anthropic.com/en/docs/claude-code/memory) [OpenAI Codex CLI](https://github.com/openai/codex)

8. **Durable state/checkpoints are the antidote to context bloat.** LangGraph’s persistence model stores thread state/checkpoints for durable execution, replay, human-in-the-loop, and recovery; LlamaIndex Workflows similarly frames agentic systems as event-driven workflows with explicit state. **Pi influence:** store durable artifacts outside the chat transcript: task brief, assumptions, retrieval queries/results, selected files, plan revisions, diffs, validation outputs, and final rationale. Resume from checkpoints instead of re-sending full history. [LangGraph persistence](https://langchain-ai.github.io/langgraph/concepts/persistence/) [LlamaIndex Workflows](https://docs.llamaindex.ai/en/stable/understanding/workflows/)

9. **Evaluator loops should be explicit, bounded, and cheap-first.** Anthropic identifies evaluator-optimizer as a core workflow pattern where one LLM produces and another evaluates/refines; coding-agent practice adds deterministic evaluators such as tests, linters, type checks, and diff review. **Pi influence:** separate implementer and evaluator prompts; evaluator receives acceptance criteria, diff, and relevant snippets only; cap retry count; record failed checks as durable evidence. [Anthropic: Building effective agents](https://www.anthropic.com/research/building-effective-agents) [Claude Code best practices](https://www.anthropic.com/engineering/claude-code-best-practices)

10. **Prompt/program optimization should be metric-driven.** DSPy treats prompts and LM calls as optimizable programs, using task metrics and optimizers to tune instructions, demonstrations, and pipelines rather than hand-tweaking prompts indefinitely. **Pi influence:** version prompts, retrieval parameters, and context budgets; build a benchmark set from real Pi tasks; optimize for success-per-token, edit accuracy, and validation pass rate before increasing autonomy. [DSPy optimizers](https://dspy.ai/learn/optimization/optimizers/) [DSPy docs](https://dspy.ai/)

11. **Guardrails and handoffs should be designed into the workflow, not added later.** OpenAI’s agent guide frames agents as systems where models choose tools under instructions and guardrails; it recommends clear task boundaries, tool design, evaluation, and human escalation for risky decisions. **Pi influence:** make escalation points explicit: unclear requirements, destructive filesystem changes, dependency/security changes, failing validations after budget, or low retrieval confidence. [OpenAI: A practical guide to building agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)

## Recommended Pi Cartographer workflow shape
- **Default path:** `intake -> durable plan -> repo-map skim -> lexical/symbol retrieval -> targeted snippet pack -> implementation -> deterministic validation -> evaluator review -> compact final record`.
- **Context budget policy:** stable instructions and repo map are cached/compacted; dynamic context is mostly retrieved snippets with file-line citations; summaries/checkpoints replace transcript history after each phase.
- **Retrieval policy:** lexical/symbol search first; repo graph ranking for expansion; optional semantic retrieval only for conceptual discovery, docs/issues, or when lexical queries fail.
- **Subagent policy:** use only for parallel research, large-repo reconnaissance, independent review, or test/eval fanout; each worker gets a narrow brief and returns a short artifact.
- **Optimization policy:** measure outcome per token and validation success before adding autonomy; tune prompts/retrievers using historical tasks and evaluator datasets.

## Gaps
- Live web search was not exposed in this runtime, so URLs and very recent product-doc changes should be revalidated by the supervisor if freshness is critical.
- Pi-specific thresholds need local measurement: optimal repo-map token budget, lexical-vs-semantic retrieval mix, subagent break-even point, and retry/evaluator caps.
- Recommended next step: create a small benchmark from real Pi tasks and measure success rate, validation pass rate, wall time, and tokens for baseline workflow vs added repo map, durable checkpoints, evaluator loop, and subagent fanout.
